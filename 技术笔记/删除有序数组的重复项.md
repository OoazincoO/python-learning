# 删除有序数组中的重复项：快慢双指针原地去重

> 日期：2026-11-11 ｜ 第 26 题 ｜ #LeetCode #双指针 #数组

## 问题 / 背景

给一个已排好序的数组 nums，原地删掉重复元素，让每个数只出现一次，返回不重复的个数 k。判题的主函数会把返回值赋给 k，只检查下标小于 k 的前 k 个值，==k 后面的内容不管==。不另开新数组，额外空间要求 O(1)。

> [!info] 判题机制
> 返回 k 后只检查前 k 个值；后面的残留内容作废、不影响判题，所以"删除"其实是覆盖写，不用真删。

## 我的解法 #快慢双指针

- **思路**：快慢双指针。slow 停在已确认不重复的最后一个位置，fast 从下标 1 开始往后扫；fast 找到跟 slow 不一样的新数，就先让 slow 前进一格，再把新数抄过去；一样就直接跳过。排好序意味着重复的数一定挨在一起，所以==只跟队尾比就够了==，不用[[字典(dict)|字典]]。
- **复杂度**：时间 O(n)，空间 O(1)
- **结果**：本地三组测试通过——[1,1,2] → 2，前两位 [1,2]；[0,0,1,1,1,2,2,3,3,4] → 5；[1,2,3] → 3；==2026-11-11 力扣正式提交通过 ✅==

```python
class Solution:
    def removeDuplicates(self, nums: list[int]) -> int:
        if not nums:
            return 0
        slow = 0
        for fast in range(1, len(nums)):
            if nums[fast] != nums[slow]:
                slow += 1
                nums[slow] = nums[fast]
        return slow + 1
```

> [!tip] 快慢双指针模板
> slow 指向已确认区末尾，fast 负责探路；fast 遇到新值就先 slow+=1 再覆盖写入。原地算法的"删除"都是覆盖，不是真删。

## 踩过的坑 / 卡点 #易错点

> [!warning] 边遍历边 del 是双重坑
> 删一个，后面的数全体前移，下标错位会跳过元素；每次 del 都要搬数据，总复杂度退回 O(n²)。要"删"就覆盖写，残留值留着作废。

- 第一版想套[[Two Sum-暴力到哈希的优化|Two Sum]]的字典判重：只查 `if num in seen` 却从没往 seen 里存，条件永远不成立——==先查后存，存的那一步不能少==
- 边遍历边 `del nums[i]`：删一个，后面的数全体前移，下标错位会跳过元素；且每次 del 都要搬数据，总复杂度退回 O(n²)
- 第一版没写 return：函数头写了 `-> int`，最后必须把 k 返回给主函数
- 比较对象写成 `num[fast-1]`：num 这个变量根本不存在；该跟 slow 位置的队尾比，不是跟前一个比
- 一度以为赋值是把值搬走：其实 `nums[slow] = nums[fast]` ==是复制，源位置的值还在==；被盖掉的只是重复数，前 k 个算数、后面残留作废。slow 永远落后于 fast，不会盖到还没读的数

## 更优解法 / 其他思路

- **思路**：字典判重（自己的第一版想法）对无序数组可行，但这题数组有序，重复必相邻，双指针就是为这个条件量身定的，不需要字典
- **为什么快/好**：字典法要 O(n) 额外空间、del 又慢；双指针一遍扫完、只在原数组上抄写，一分额外空间不用
- **复杂度**：时间 O(n)，空间 O(1)

## 一句话总结（费曼检验）

==双指针去重不是真删，是把不重复的数依次抄到前面==：返回个数 k，前 k 个算数，后面作废。
